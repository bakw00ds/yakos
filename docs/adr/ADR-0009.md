# ADR-0009: Typed decision providers (TypeSafe Jev) as a hook-side abstraction, not a runtime

**Status:** Proposed (K-111; operator confirmation of the pilot surfaces, egress level and budget cap pending)
**Date:** 2026-09-29
**Deciders:** operator
**Refs:** K-111 design report (operator scratchpad, 2026-09-29), `cli/lib/runtimes/README.md` (runtime contract), `docs/runtime-matrix.md`, `rule:cache-stability`, `rule:secret-handling`, `rule:verification-discipline`, `lib/hooks/README.md` (injection-scan trust boundary), TypeSafe docs: https://docs.typesafe.ai/api, https://docs.typesafe.ai/models, https://docs.typesafe.ai/model-jaggedness/jev-1.13

---

## Context

TypeSafe's Jev (early access since 2026-09-15) is a "System One" model:
`POST https://api.typesafe.ai/v1/systemone` takes a text/JSON `state`
and a map of typed questions (Choice, Score, Noul) and returns
probabilities and a confidence per answer, never text
(https://docs.typesafe.ai/api). It is priced at $0.042 per million
input tokens with free output, limited to 32k tokens of state, pinned
by version (`jev-1.13.0`; aliases move), and documented as *not* a
replacement for the LLM driving a coding agent
(https://docs.typesafe.ai/introduction/coding-agents).

yakOS makes many cheap judgments today that are either regex/heuristic
(supervisor stream pre-filter, output-injection scan) or expensive
LLM calls (haiku supervisor findings, the 3-vendor plan-quality panel),
or prose the lead applies by hand (CI flake classification). The
operator's ask is to "add jev and route tasks to jev that make sense",
never on the code-writing path, piloted behind the existing hook,
injection, and parity harnesses.

yakOS's only existing extension point for an external model is the
runtime adapter contract (`yk_rt_<name>_{id,check_cli,check_auth,
capabilities,materialize_agents,cleanup_agents,launch,dispatch}` in bash;
`runtime.Adapter{Name,Available,Dispatch}` in Go). That contract models
*sessions that run agents and return text*. Jev has no session, no
agent prompt, no text output, and no tools. Six of the eight verbs would
be no-ops or misrepresentations; `ValidateTier` rejects non-tier models;
the bash resolution chain could select a runtime named `jev` as a
*fallback* for a text-producing agent; cost readers group by `runtime`;
and a hook wanting a 300 ms decision would have to spawn a full
`yakos dispatch`.

Constraints that shape the decision:

- **Fail-closed.** No blocking gate may fail open because a third-party
  API is slow or down. Claude Code times out command hooks at 600 s by
  default and a timed-out *PreToolUse* hook does not block.
- **Cache stability.** Nothing volatile may enter the cached prompt
  prefix (`rule:cache-stability`).
- **Secrets.** Credentials live in environment variables only, never in
  `settings.json`/`.yakos.yml`, and one provider's key is never forwarded
  to another provider's subprocess (`runtime/env.go` allowlist).
- **Data egress.** Tool payloads can contain source code and secrets.
  TypeSafe does not train on inputs but retains them "as long as
  reasonably necessary" and processes them for telemetry and abuse
  monitoring; ZDR is enterprise-only.
- **Model jaggedness.** TypeSafe documents weaknesses on adversarial
  content, negations, indirection, and arithmetic, and advises pinning
  versions and tuning thresholds on your own labelled data.

## Decision

1. **Jev is integrated as a *decision provider*, not a runtime.**
   A new Go package `cli-go/internal/decision` defines a
   provider-neutral `Provider` interface (`Available`, `Decide`) over
   Choice/Score/Noul questions, with three implementations: `jev`
   (raw `net/http`; no Go SDK exists), `mock` (fixture-driven, used by
   all CI and parity tests), and `none`. Bash hooks reach it through
   one CLI verb, `yakos decide <surface>`, the same way they reach
   `yakos dispatch` today; Go hooks call the package. Jev is **not**
   added to `runtime.Known`, `YK_RT_KNOWN_BUILTIN`, the console
   `RUNTIMES`, or any fallback list, and `yakos validate` /
   `yakos agents lint` reject `runtime: jev` in agent or Flows-node
   frontmatter with a hard error.

2. **Decision points are explicit and reviewed.** A Jev call can only
   originate from a registered decision point in code that references a
   question set in `lib/decisions/<surface>.yaml` (schema id, pinned
   model version, questions, thresholds, allowed state fields, egress
   list). The file's sha256 is logged with every decision. Aliases such
   as `jev-latest` are rejected by `validate`.

3. **Per-surface mode table in `.yakos.yml`**, default `provider: none`:
   `decisions.surfaces.<surface>.mode ∈ {off, shadow, prefilter}`, plus
   `budget.{max_calls_per_session, max_usd_per_day}` and
   `egress.{level, never_paths}`. `YAKOS_DECISION_DISABLE=1` is a global
   kill switch. Credentials are `TYPESAFE_API_KEY` (optional
   `TYPESAFE_BASE_URL`) from the environment only, never forwarded to
   dispatched runtimes.

4. **Fail-closed invariants, enforced in the package and the schema:**
   - Unavailable/timeout/error/budget/breaker ⇒ the existing
     deterministic path runs unchanged; the decision log records why.
   - In `prefilter` mode Jev may only *add* to a deterministic result
     (union). A regex/glob hit is never suppressed by a Jev answer.
   - No Jev answer is the sole source of a blocking (exit 2) decision
     until the surface has a recorded promotion
     (`yakos decide promote`, operator-run) whose eval met the
     per-surface threshold. Schemas carry `may_block: false` until then
     and `validate` refuses `may_block: true` without a promotion record.
   - `shadow` mode is asynchronous (0 ms added to the hook);
     `prefilter` mode is synchronous with a 1,500 ms deadline and at most
     one retry. No PreToolUse gate calls Jev in the pilot.

5. **Pilot surfaces and order:** supervisor stream pre-filter
   (shadow → prefilter), output-injection scan (shadow → prefilter;
   Flows block path last, zero-FP requirement), CI failure
   classification (`yakos ci classify`, advisory only), plan-quality
   scoring (shadow only; at most a weighted fourth judge later).
   Routing/tier selection is shadow-log-only and deferred: a live
   downgrade is on the code-writing path by effect and would bypass the
   existing Wilson-CI promotion gate.

6. **Egress is `strict` by default:** previews (≤ 2 KB) rather than file
   contents for the supervisor surface; tool output ≤ 50 KB for the
   injection surface with `Read` output opt-in; secret-pattern redaction
   (`secret-scan.sh` patterns + credential-assignment, JWT, Bearer
   shapes) before every call; paths under `egress.never_paths` never
   leave; redaction counts logged.

7. **Observability:** one record per call in
   `~/.yakos-state/decision-log.ndjson` (surface, schema hash, model
   served, mode, enforced, answers, baseline verdict, `agree`, usage,
   cost, latency, status). Not written to the dispatch-log. `yakos
   doctor --probe-decision` reports key presence (set/not set only),
   breaker/budget state, served model version, and drift from the
   pinned version. Console shows a per-decision `jev · shadow|live`
   chip on supervisor findings and scan warnings; Jev is not a
   selectable chat runtime.

## Consequences

**Positive:**

- The guardrail "Jev never runs an agent with Edit/Write/Bash" holds by
  construction: there is no runtime, flag, or fallback that can route
  an agent to it, and the validator says so explicitly.
- Every surface degrades to today's behaviour when Jev is absent; the
  pilot is shadow/advisory, so early-access instability (429/529,
  alias drift, "dynamically adjusting" limits) cannot break a session.
- Cost is bounded by construction (per-session and per-day caps; the
  pre-filter is ≈ $0.00005 per call) and visible to finops via the
  decision log.
- Question sets and thresholds are reviewed source with hashes, so a
  threshold cannot be silently applied to a different question or model
  version — TypeSafe's own recommended practice.
- The abstraction is provider-neutral; an `llm-judge` or `local-llm`
  provider can answer the same schemas later, avoiding lock-in.
- The supervisor pilot forces two pre-existing fixes into the open
  (`tool_input.command` unread by the stream; Go-tier supervisor never
  launched), improving the baseline independently of Jev.

**New risks:**

- **C1 — Data egress.** Redacted previews and tool outputs leave the
  machine to a US-hosted early-access vendor that retains inputs for an
  unspecified period. Mitigated by `strict` egress, redaction, secret
  path exclusion, and per-project `provider: none`; residual risk is the
  operator's call per project.
- **C2 — False confidence.** Calibration is a population property; an
  individual answer can be wrong at high confidence. Mitigated by the
  union rule, no sole-source blocks, and per-surface labelled
  thresholds.
- **C3 — Adversarial mis-scoring.** The vendor lists adversarial text
  as a weakness; injection text is adversarial by definition. Jev
  cannot execute instructions (no tools, no text), so the failure mode
  is a missed detection, which the regex stage and the nonce delimiter
  still cover.
- **C4 — Hook latency in `prefilter` mode.** Up to ≈ 1.8 s per
  PostToolUse call on Edit/Write/Bash. Mitigated by the deadline and by
  keeping `shadow` asynchronous; if the measured p95 exceeds 1 s the
  surface stays in shadow.
- **C5 — Vendor drift.** Aliases move and pricing/limits may change.
  Pinning plus `doctor` drift detection plus automatic re-shadowing on
  version mismatch.
- **C6 — Two lists to keep in sync.** The `decisions.surfaces` table
  and the `lib/decisions/*.yaml` files add configuration surface;
  `validate` checks that every enabled surface has a schema and every
  schema names a registered decision point.

**Residual trust boundary (round-2 review R2-6).** A cloned project's
environment for hooks can redirect the user-level policy file (through
`YAKOS_DISPATCH_LOG`, which relocates the whole state directory) or
intercept traffic through proxy or CA environment variables. That is the same
trust level as any project hook that can read `TYPESAFE_API_KEY`: a project you
run hooks from is trusted with the key. The host allowlist, the policy ceiling
and the agent guardrail bound accidents and untrusted agents, not a hostile
project running hooks as you.

## Alternatives considered

**A. Jev as a `yk_rt_jev` runtime adapter (the brief's first framing).**
Rejected: six of eight verbs are no-ops or lies, `dispatch`'s text
contract does not fit, the resolution chain could fall back to/from it,
tier validation and cost analytics would need fake tiers, and the
tools-vs-runtime guardrail would have to be bolted on rather than
structural.

**B. Jev via `yakos dispatch` with a pseudo-agent (`supervisor-jev`).**
Rejected: a hook would pay roster compose, dispatch-log events, and a
600 s default timeout for a sub-second HTTP call; agent frontmatter has
no way to express questions and thresholds; the agent would appear in
the console roster and slash menu.

**C. Agent frontmatter `decision-provider: jev` on judgment-only agents
(`supervisor`, `model-routing-eval`).** Rejected: those agents read
files and write cited rationale or run dispatches and statistics; Jev
answers neither. The Jev-shaped piece is a specific decision inside
their workflow, which decision points capture precisely.

**D. Call TypeSafe through OpenRouter or LiteLLM.** Not chosen for the
pilot: adds a second third party to the egress path and a second key;
the direct API is a single documented endpoint. Kept possible via
`TYPESAFE_BASE_URL` for operators who prefer their gateway.

**E. Replace the regex stages outright with Jev.** Rejected: the regex
stages are deterministic, parity-tested, free, and offline; the vendor's
own jaggedness page argues for keeping code-computable checks in code.

## Migration / rollout

Phase 2 PRs (one reviewable PR each): P0 this ADR → P1 decision package
+ `yakos decide` + doctor + validator → P2a stream reads
`tool_input.command` (fix) → P2b supervisor shadow pre-filter → P3
injection-scan shadow → P4 `yakos ci classify` → P5 plan-quality shadow
→ P6.x per-surface promotions with attached eval reports → P7 console
chips (optional). No PR touches `cli-go/internal/runtime/claude.go`
or any cached-prefix construction. Rollback at any point is
`decisions.provider: none` (or `YAKOS_DECISION_DISABLE=1`), which
restores today's behaviour byte-for-byte on every surface.
