# ADR-0010: Harness-native routing: yakOS spawns the official binaries and never holds a vendor login

**Status:** Accepted (K-155, recording the decisions of the multi-harness router program)
**Date:** 2026-10-08 (facts below are dated; re-check them before relying on them)
**Deciders:** operator (decisions of 2026-10-05)
**Refs:** K-132 to K-154, `docs/routing.md`, `docs/runtime-matrix.md`, ADR-0006 (SDK sidecar), ADR-0009 (decision providers), ADR-0011 (gateway), ADR-0012 (REPL), `rule:cache-stability`, `rule:secret-handling`

---

## Context

yakOS used to run everything through Claude Code. The operator wants one prompt
or UI to drive Claude Code, Codex and Antigravity (`agy`), pick between them
by rule, and later use local models. Two ways to do that exist:

1. **Speak each vendor's API** with a stored credential, and run the agent
   loop in yakOS.
2. **Drive each vendor's own harness** (`claude`, `codex`, `agy`), which owns
   the login, the tools and the agent loop, and route between them.

The first needs yakOS to hold or replay a subscription login, which the
vendors' terms restrict. The second does not. This ADR records that choice, the
vendor facts it rests on (with dates), and the one assumption that no source
settles.

## Decision

1. **Routing is harness-native.** The unit yakOS routes is a (runtime, model)
   pair. Every dispatch, from every transport (console Chat, REPL, MCP,
   JSON-RPC, REST, gRPC, Flows, the OpenAI-compatible endpoint), goes through
   one chokepoint, `dispatch.Service`, where `internal/router` picks the pair
   by deterministic, explainable rules (`docs/routing.md`). A per-harness
   `LineParser` normalizes each harness's stream; there is no protocol client
   for any harness.
2. **Subscription harnesses are spawned as the official binary only.** yakOS
   never extracts, caches, copies, refreshes or replays an OAuth token. It
   never calls the Codex app-server `account/login` method. Login happens
   through the vendor's own flow (`claude` `/login`, `codex login`, a one-time
   interactive `agy`). A harness receives only the environment allowlist of
   `runtime.FilterEnvFor`.
3. **yakOS owns what it must to stay out of the operator's own session.**
   Codex runs under `CODEX_HOME=~/.yakos-state/codex-home`, created by
   `yakos auth login codex`, so a dispatch and the operator's interactive codex
   do not share one `auth.json`. A project cannot relocate it (K-129).
4. **Never route a subscription harness to another vendor's model, and never
   route Claude Code to a non-Claude model.** Per-class routing of Claude Code
   moves between Claude models only (env aliases, K-141; the gateway,
   ADR-0011). Crossing vendors happens at the harness boundary: a different
   runtime is chosen, with its own login and its own handoff digest.
5. **API-key paths are separate and gated.** The Agent SDK sidecar starts only
   with `ANTHROPIC_API_KEY` (K-137). The gateway holds the operator's API key
   and refuses a subscription token unless a flag says otherwise (ADR-0011).
6. **Sandbox by default, honestly described.** codex runs in its OS sandbox;
   agy gets `--sandbox`, which K-158 measured as a write guard and not a
   containment boundary. The wording is fixed in `docs/runtime-matrix.md`.
7. **Stricter-only project config.** Anything that loosens routing, egress,
   sandbox or listeners is read only from owner-only, non-symlink files under
   `~/.yakos-state`. A project `.yakos.yml` can tighten.
8. **Route metadata stays out of the cached prefix.** Route reasons, ids and
   handoff notices travel in SSE, transcript turns, ledger rows and the tail
   turn, never in a system prompt, `--append-system-prompt` or the `--agents`
   JSON (`rule:cache-stability`). A switch of harness is shown to the operator
   as a prompt-cache reset.
9. **Local providers are a slot, not a feature.** See "Local providers" below.

### The assumption no source settles

No document found addresses a **local orchestrator that spawns the unmodified
`claude` binary under the operator's own login** and drives it through
`claude -p` with `--output-format stream-json`. yakOS treats this as allowed:
it is what Claude Code's own non-interactive mode exists for, the operator is
the person logged in, and yakOS touches no token. This is an assumption, not a
confirmed permission. It holds only while yakOS:

- spawns the official binary and does not alter it;
- does not read, copy, forward or store the login (the child inherits its own
  keychain or environment access, nothing more);
- does not offer the login to anyone else (no multi-user sharing of one
  subscription through the networked console, no relay of a subscription token
  to a gateway client);
- keeps the per-vendor rate behaviour of the harness (no pool of logins).

If Anthropic, OpenAI or Google state otherwise, the harness in question moves to
API-key use or is disabled by `router.disable_runtimes`, and this ADR is
superseded for that vendor.

### Local providers

A local model server (Ollama 0.14 and later serving `/v1/messages`, LM Studio,
llama.cpp) is the intended next provider kind and is **documented as a type
only in this round; no code or test exists for it.** The shape is a provider
entry of `kind: local` with an `api` that says which wire the server speaks:
`anthropic-messages` (Claude Code against `ANTHROPIC_BASE_URL`, as the gateway
does) or `openai-responses` (Codex `--oss --local-provider`, and the
OpenAI-compatible endpoint). `docs/routing.md` ("Local providers: a documented
slot") has the table. What the registry already has for it: `billing: local`,
which counts tokens and never dollars, and the provider label. A local model would
satisfy the sensitive class, because its data does not leave the host. Anthropic does
not support Claude Code against non-Claude models, so a local provider behind
Claude Code would be the operator's own responsibility and never a default.

## Consequences

- Routing needs no vendor credential in yakOS, and no vendor can be made to
  receive another vendor's token through yakOS.
- yakOS depends on each harness's CLI surface (flags, JSON streams). The
  parsers are recorded-fixture tested and `yakos doctor --policy` flags a CLI
  whose version no recorded fixture covers. A harness upgrade can break a
  parser; the fallback is the buffered raw stream.
- The router cannot offer a per-request, cross-vendor switch inside one Claude
  Code session. A conversation changes harness only at a turn boundary, by
  operator action, with a digest and a cache-reset banner.
- Accounting of subscription harnesses is tokens only; dollars stay `api`-only
  (K-136).
- The assumption above is a standing risk. It is written down so it is reviewed
  when a vendor's terms change, not found later.

## Alternatives considered

- **Direct API clients per vendor** (stored keys or tokens): rejected. It needs
  yakOS to hold credentials, and subscription logins cannot be used that way.
- **A generic OAuth proxy in the gateway:** rejected (ADR-0011). It is the
  behaviour the vendors' terms forbid.
- **ACP or the codex app-server as the interface:** deferred. No subscription
  harness benefits today; the slot stays behind `interactive.Engine`.
- **Learned routing in the live path:** deferred. Selection stays deterministic
  and explainable; the offline eval (`internal/routing`) keeps its promotion
  gate.
