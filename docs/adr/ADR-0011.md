# ADR-0011: The Anthropic pass-through gateway (127.0.0.1:7897) and its trust boundary

**Status:** Accepted (K-151)
**Date:** 2026-10-07
**Deciders:** operator
**Refs:** K-141 (`gateway_classes`), K-140 (sensitive class), K-150 (OpenAI-compatible endpoint, same package layout), `docs/routing.md`, `rule:cache-stability`, `rule:secret-handling`

---

## Context

Claude Code can be pointed at a different API base with `ANTHROPIC_BASE_URL`.
With `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` it also labels each request with
`x-claude-code-request-class` (`main`, `subagent`, `workflow`, `compaction`,
`auxiliary`, `side_reply`) and `x-claude-code-agent-type`. Both names were read
out of the installed CLI (2.1.293). That is enough to route a class of request
(for example sub-agents) to a cheaper Claude model without touching the prompt.

A local proxy that sees every Claude Code request also sees every credential
and every prompt. The gateway therefore has to be small, loopback-only, off by
default, and unable to send anything anywhere except Anthropic.

## Decision

`yakos serve --gateway` (or `anthropic_gateway: true` in the trusted user
policy; a project file cannot enable it) serves `internal/gateway/anthropic` on
`127.0.0.1:7897`. `yakos start --routed` launches Claude Code with exactly two
variables added: `ANTHROPIC_BASE_URL=http://127.0.0.1:7897` and
`CLAUDE_CODE_GATEWAY_HINT_HEADERS=1`.

Trust boundary, each point backed by a test:

1. **Off by default; loopback only.** `New` refuses any non-loopback bind.
   Host (DNS rebinding) and Origin (browsers) are checked before anything is
   read. A failed bind disables the gateway loudly instead of falling over.
2. **One upstream.** Requests go to `https://api.anthropic.com` (TLS 1.2+,
   host pinned in code, no setting changes it). Redirects are never followed, so
   a credential cannot be replayed to another host. A registry `billing=local`
   slot exists as a type (`KindLocal`) only; no transport is built for it.
3. **Routes.** `POST /v1/messages`, `POST /v1/messages/count_tokens`,
   `GET /v1/models` (Claude ids only). Everything else is 404/405.
4. **Verbatim.** Request and response headers pass unchanged except
   hop-by-hop ones. SSE is flushed as it arrives, ping frames included. Error
   bodies and statuses are Anthropic's own. There is no retry. A reply cut off
   upstream drops the client connection rather than ending cleanly.
5. **Credentials.** The client's own `x-api-key` / `Authorization` is forwarded
   on that one request and nowhere else: never logged, stored, cached or reused.
   A request that carries none gets the operator's `ANTHROPIC_API_KEY` from the
   daemon's environment (a local process can therefore use the key through the
   gateway; that is the cost of the convenience, and the reason for 1). A
   subscription OAuth token (`sk-ant-oat*`, or an `oauth-` beta flag) is
   **refused with 403** unless the operator starts the gateway with
   `--gateway-passthrough-subscription`. The default exists because a
   subscription token is not an API credential and routing it through a third
   process is the operator's decision, not ours.
6. **Rewrite is narrow.** The only change ever made to a body is the `model`
   value, spliced in place so every other byte (and the prompt-cache prefix)
   is unchanged. It happens only when (a) a hint header names a class, (b) the
   trusted policy's `gateway_classes` table assigns that class a concrete Claude
   id, and (c) the incoming model is a Claude id. Today the router vocabulary
   makes `subagent` the only class a header can select; the tier classes
   (`opus`, `sonnet`, `haiku`, `fable`) stay environment aliases (K-141).
   Anything ambiguous (duplicate `model` keys, non-string model, bad JSON)
   passes untouched. Route metadata never enters a prompt, system prompt or
   `--agents` JSON.
7. **Sensitive class before any non-primary upstream.** If a route ever picks an
   upstream that is neither the primary nor a local slot, the body is scanned
   (K-140) first and a sensitive request is refused with 403. Today every route
   is primary, so this is a guard, tested with an injected upstream.
8. **Ledger.** Each request writes one `gateway_request` event through
   `dispatch.Account`: surface, endpoint, class, model in/out, status, token
   counts, billing (`api`/`subscription`), and a fixed-vocabulary refusal
   reason. No body, header or credential; strings pass `logIdent`. A log-sink
   test runs every path against the real ledger and a capturing log handler and
   asserts no credential, prompt text or upstream address appears.
9. **Bounds.** 32 MiB request body, 64 requests in flight (429 above that).

## Consequences

- A `--routed` Claude Code cannot reach the API while the gateway is down;
  `yakos start --routed` warns when nothing listens on 7897.
- The hint headers are a Claude Code feature that may change; the gateway
  treats an unknown or missing class as "no rewrite", so it degrades to a
  plain proxy.
- Residual risks: the gateway cannot defend against another process of the same
  user (it could read the daemon's environment anyway); an operator who
  enables passthrough accepts that the subscription token transits the daemon
  process; token counts for responses in an encoding other than gzip or
  identity are recorded as zero.
- Local-slot transports (`KindLocal`) are future work.
