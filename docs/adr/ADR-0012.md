# ADR-0012: `yakos start` opens a yakOS REPL; the vendor TUI becomes `--native`

**Status:** Accepted (K-154). Partially supersedes ADR-0008 (the default of
`yakos start`; the PTY relay of ADR-0008 stays and backs `/attach`).
Revives the thin-client idea of ADR-0007 (Tier C) on top of the daemon
endpoints that exist now.
**Date:** 2026-10-07
**Deciders:** operator (decision of 2026-10-05, multi-harness router program)
**Refs:** `cli-go/internal/repl`, `cli-go/cmd/yakos/cmd_start_repl.go`,
`cli-go/internal/consoleui/chat_handler.go` (`/api/chat/*`),
`cli-go/internal/start/pump_unix.go`, ADR-0007, ADR-0008, ADR-0005,
`rule:cache-stability`

## Context

ADR-0008 made the native `claude` TUI the thing `yakos start` shows and
mirrored it to the browser. Since then the console Chat pane gained a
router (K-148): one conversation can run on claude, codex or agy, with a
route chip per turn, `@runtime` overrides and handoff digests. A vendor TUI
cannot show any of that, and it ties a terminal session to one harness.
The operator decided that `yakos start` should be a yakOS REPL and that the
vendor TUI stays one flag away.

## Decision

1. Under `YAKOS_IMPL=go`, on a terminal, `yakos start` opens the REPL. It is
   a line-oriented streaming client of the daemon's `/api/chat/*` endpoints:
   no TUI library, no new dependency. It renders tokens, thinking, tool
   cards, route chips, handoff banners and AskUserQuestion (answered through
   `/api/chat/answer`).
2. `yakos start --native <runtime>` is today's exec path, unchanged (the
   argv is pinned by a golden generated from the pre-REPL binary). The REPL
   is also not used with `--no-repl`, `--dry-run`, `--print-agents`,
   `--print-env`, `--share-terminal`, `--direct`, the session passthrough
   flags, networked-console flags, a non-terminal stdin, or a `--runtime`
   that is not claude, codex or agy: those keep the exec path.
3. The daemon owns the conversation, router, transcript and cost ledger. The
   REPL holds a harness, a model, a conversation id and one session id. It
   uses the loopback operator identity, so the same conversation appears in
   the browser Chat pane.
4. The daemon is auto-started through the existing `spawnDaemonFn` seam. If
   that fails the REPL prints a fixed, path-free message and points at
   `--native`. The bearer token is read from `<state>/console-token` and is
   never created by the REPL; it is sent only to a loopback address.
5. `/attach <runtime>` runs `yakos start --native <runtime> --share-terminal`
   as a child on the same terminal: the native TUI runs under the PTY of
   ADR-0008 (T2 relay), mirrored in the console Terminal pane, and the REPL
   resumes when it exits. The REPL itself never owns a PTY.
6. The bash launcher keeps the native TUI. It accepts `--native <runtime>`
   as an alias of `--runtime` and `--repl` stops with the Go-only message.

## Consequences

- Terminal and browser share one routed conversation; a message can go to
  any harness with `@codex` and shows its handoff banner.
- `yakos start` now needs a daemon for the default path. Auto-start covers
  the common case; `--native` is the escape hatch with no daemon.
- Turns are one-shot dispatches continuing the same conversation id; the
  REPL does not run the persistent interactive engine, so AskUserQuestion
  works only when the daemon was started with structured questions.
- Route metadata stays in SSE and the transcript; the REPL builds no system
  prompt (`rule:cache-stability`).
- Scripts that piped into `yakos start` keep working: a non-terminal stdin
  selects the exec path.
- ADR-0008's statement that `yakos start` shows the native TUI by default is
  superseded; its PTY relay, security analysis and `--share-terminal` are not.
